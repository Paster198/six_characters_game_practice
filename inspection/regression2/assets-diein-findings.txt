=========================================

Strong native fault candidate, separate from central difficulty-state logic
------------------------------------------------------------------------
The original helper 8a6048 returns false for every song other than diein and
every difficulty other than ETR (4). For DIE IN ETR it checks DJMAX purchase
requirements, but even when pack-ownership checks succeed, it unconditionally
loads the ETR difficulty's UnlockCondition pointer and calls its evaluator:
  8a62a4: w0 = 4
  8a62a8: difficulty-index mapping 863e1c
  8a62b0: x8 = Song.difficulties[index] (Song+228)
  8a62b4: x0 = [x8] (difficulty UnlockCondition pointer)
  8a62b8: call 1313478
  131348c: ldp x22,x23,[x0,#28] -- no null guard

Original assets/songs/unlocks has a diein/4 object with conditions on nightmare
ETR, wereallgonnadie ETR, potential and credits. The offline empty unlocks list
removes this object. This path is not dependent on a story flag and is distinct
from the central 1809390 null-vtable path.

There are four direct helper callers: c76d10, d94114, 12fbc74, 131e188. The native
agent's patch at 8a60f4 uses the existing false-return epilogue 8a6340. It occurs
after the temporary ID string cleanup and w21=0, and before constructing the
purchase-pack vector. The analogous Aether Crest ETR patch at 114e2ec ->114e58c
has the same safe object-lifetime shape. Independent review found no blocker.
Original Aether Crest ETR also has a real unlock object, so empty unlocks would
otherwise expose its identical unchecked call at 114e4b0.

Limit: no device crash stack is available. If the reported DIE IN crash is on
PST/PRS/FTR, this ETR-only helper cannot explain that occurrence.
