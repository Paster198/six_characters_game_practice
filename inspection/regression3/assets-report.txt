byd_local_unlock investigation and why a metadata-only fix is insufficient
------------------------------------------------------------------------
Original arcaea.apk has 18 BYD songs with byd_local_unlock=true, including all
four Inscribed songs. The other 50 BYD songs omit it.
Infinity source and generated fix2 both omit it on all 68 BYD songs.
Generator clear_gates also removes this field, but Infinity already lacks it.
Key VA 0x5332ca parsed at 0x193b824..8bc; missing sets W24=0 at 0x193b8c0.
0x193ba38 saves W24 at SP+0x100. 0x193f734..40 passes callerSP+0x60.
Constructor 0x195dbdc reads FP+0xc0 == callerSP+0x60, masks boolean, and
0x195dc0c stores Song+0x161.
9bcf88(non-forced) checks ratingClass==3 at 9bd090, loads this byte at 9bd098,
and sends zero to 950c88 via 9bd044. Thus preserving/setting true changes this
particular branch, but does NOT solve all download status checks.
13360a4 first calls 9bcf88 with caller's forced flag. It then unconditionally
sets W2=1 at 13360cc and calls 9bcf88 a second time at 13360dc.
9bcf88's 9bcfbc sends W2=1 directly to 950c88 (call 9bcfdc), bypassing +0x161.
Consequently metadata-only byd_local_unlock=true is not a complete repair.

Independent review of proposed one-instruction native repair
-----------------------------------------------------------
Factory 0xa16fb0 returns its vector via X8, copied to X19.
0xa16fd8/0xa16fdc zero all three vector pointers before any resource append.
0xa16ff0 constructs a local copy of Song id at SP+0x20.
0xa16ff4 reads Song+0x1c0 (remote_dl).
Original 0xa16ff8 CBZ W8,0xa17200 skips base remote assets but still permits
0xa1720c..18 to query BYD existence and append a '<song>_3' requirement.
0xa17280..90 additionally checks BYD audioOverride and appends '<song>_audio_3'.
0xa172f8 onward can append additional_files as remote requirements as well.
Proposed change to CBZ W8,0xa17430 makes local songs return an empty remote
requirements vector. The initialized vector stays empty on this path.
0xa17430..3c is the original destructor/free of the one constructed local
Song-id string. 0xa17440 onward is the unchanged canary/epilogue.
This target correctly preserves string cleanup, register restoration, and
the remote_dl=true original behavior. The remote factory does not check AFF
or audio contents, so returning no remote requirements does not itself claim
missing chart/audio resources exist; the local payload audit covers this APK.
This review supports the parent's single-instruction repair; no metadata change
is required for this regression. Runtime device verification remains necessary.
